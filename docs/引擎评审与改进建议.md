# 引擎评审与改进建议

> 评审对象：**Go 引擎本体**（`cmd/ximo-agent` + `internal/**`），不含 Electron 渲染层，
> 也不含后来新增的中转站网关（`internal/gateway`）与插件（`plugin/`）。
> 评审基线：`v2` 分支 `ec951de`（2026-09-26）。
> 本文所有数字与现象都可复现，复现命令见最后一节。

---

## 一、评审范围与采样偏差（先说清可信边界）

**深读过的**：`internal/provider`、`internal/storage`（含 sqlite 写队列、outbox、migrations）、
`internal/ipc` / `internal/ipcapi`、`internal/scheduler`（资源池与预算）、`internal/tool`
（接口面、权限、沙箱入口）、`internal/bootstrap`、`internal/memory`、`internal/config`、
`internal/types` 的错误分类、`cmd/ximo-agent`。

**只做过浅层浏览的**：`internal/expert`（含 151 套设计资源）、`internal/knowledge`、
`internal/context`、`internal/agent/loop.go` 内部细节、各 worker（browser / computer-use /
terminal / office / mcp / dynamic）的实现。

**因此**：下面关于"设计得对"和"结构债"的判断，在深读过的包上证据硬；在浅层浏览的包上
证据弱，**欢迎反驳**。

## 二、评分

| 维度 | 权重 | 得分 | 依据 |
|---|---|---|---|
| 架构与边界设计 | 20% | 8.5 | 端口由消费方定义（`internal/ports` 1072 行 / 7 个接口）、适配集中在装配层、三层资源闸门、统一降级语义 |
| 正确性与并发一致性 | 20% | 7.5 | 单写者队列、`fencing_token`、outbox、seq 同事务单调推进、幂等约束都扎实；扣分：流式请求按 0 token 计费（已修）、`provider_requests` 闸门未接线、无 `-race` 验证 |
| 测试 | 15% | 7.5 | 测试占比 34%、958 个测试函数、六类形态（unit/e2e/chaos/recovery/stress/fuzz）；扣分：门禁用 `test-short` 跳过 10000-run 压力用例、CI 不跑测试、无真实上游 E2E |
| 代码结构 | 12% | 6.0 | 三个 god object：`engine.go`(1884 行/57 函数)、`worker/manager.go`(1591/50)、`agent/loop.go`(1413/40) |
| 安全 | 12% | 7.0 | 密钥只存哈希/引用、多层脱敏、刻意不提供读明文接口；扣分：IPC 无鉴权、`internal/secrets` 不可移植 |
| 可运维性与发布 | 8% | 5.5 | 结构化日志 + trace_id 良好；扣分：升级脚本整条不可用（旧分支）、版本/标签卫生、无发布门禁 |
| 文档与知识传递 | 7% | 7.5 | 交接包与决策记录属优等；扣分：注释与代码漂移、README 声称不实 |
| 平台与依赖纪律 | 6% | 6.5 | 直接依赖只有 2 个（goja + modernc sqlite），非常克制；扣分：非 Windows 编不过 |

**加权：≈ 7.2 / 10**

分档锚点（便于他人复核与争论）：

- **5 分**：能跑，常见 CRUD 水准，不考虑并发/一致性/降级
- **7 分**：有生产意识、该踩的坑基本踩过，但收尾与结构欠账 ← **本项目**
- **9 分**：有自动门禁、结构收敛、声称与事实一致、跨平台可用、真实上游 E2E 覆盖

结论一句话：**技术判断力高于工程收尾力度。** 按个人/小团队项目横向比约在前 10–15%；
按"可交付外部长期运行的产品"看是中位偏上，差的是机制（门禁、跨平台、发布流程）与结构收敛。

## 三、值得保留的设计（改之前先读这一节，别误伤）

1. **端口由消费方定义、实现放装配层**：`internal/ports` 是纯接口；引擎不 import
   `internal/memory`。加/换能力不需要动核心。
2. **降级语义统一**：记忆、网关、可选能力一律"降级不阻断"，且降级必打警告（不是静默）。
3. **熔断只统计可归因上游的失败**（DNS/超时/429/5xx），401/400 不计——配错 key 不会假死。
4. **重试按错误类别分支**，且尊重 `Retry-After`（>60s 直接放弃）；流式重放另立更窄的一套，
   且只在"零输出"时重放。
5. **存储的单写者队列 + 写事务 panic 隔离 + 磁盘写满专项测试**。
6. **outbox 用租约 + `fencing_token`**（防脑裂），事件 seq 与 `runs.last_seq` 同事务推进。
7. **`tool.Tool` 接口上的五个维度**（Risk / Idempotency / Domain / SideEffect）——
   这是权限与幂等能被统一处理的前提，别退化成散落的 if。
8. **错误分类集中在 `internal/types/extras.go`**，不是散落字符串。

## 四、改进建议

### P0 —— 门禁（1–2 天，性价比最高）

#### P0-1 每次 push 跑 CI（现在只在打 tag 时构建，且不跑测试）

**问题**：仓库没有跑测试的 CI。现有 `.github/workflows/release.yml` 只在 `v*` tag
或手动触发时**构建发布物**，不做任何校验。

**影响**：Linux 编不过、`--migrate-only` 从未存在、流式丢 usage、gofmt 漂移、
注释与代码不符——这一整串问题能长期存活，根因都在这里。

**怎么改**：新增 `.github/workflows/ci.yml`：

```yaml
name: ci
on:
  push:
    branches: ['**']
  pull_request:

jobs:
  check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with:
          go-version: '1.27'      # 与 go.mod 一致
          cache: true
      - name: gofmt
        run: |
          unformatted="$(gofmt -l cmd internal tests)"
          if [ -n "$unformatted" ]; then echo "$unformatted"; exit 1; fi
      - name: vet
        run: go vet ./...
      - name: test（全量，不加 -short）
        run: go test ./... -count=1
      - name: race（ubuntu 有 gcc，Windows 上跑不了这一步）
        run: go test -race ./... -count=1 -short

  cross-build:
    runs-on: ubuntu-latest
    strategy:
      fail-fast: false
      matrix:
        include:
          - { goos: windows, goarch: amd64 }
          - { goos: linux,   goarch: amd64 }
          - { goos: darwin,  goarch: arm64 }
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-go@v5
        with: { go-version: '1.27', cache: true }
      - run: CGO_ENABLED=0 GOOS=${{ matrix.goos }} GOARCH=${{ matrix.goarch }} go build ./...
```

**顺序建议**：`check` 立即启用；`cross-build` 先只跑 windows，等 P1-4 修完再把
linux/darwin 打开（否则会一直红）。

**验收**：故意提交一个未 gofmt 的文件 → CI 必须红；修掉 → 绿。

#### P0-2 给闸门加一个"全量"动词

**问题**：`build.cmd verify` 走的是 `test-short`，它跳过
`internal/storage/stress_test.go` 的 `TestStressManyRunsZeroCorruption`、`internal/engine/crash_test.go`
的三个真崩溃恢复用例，并把 `tests/stress` 的 N 从 10000 降到 200。也就是说
**"10000 run 零损坏"这条红线从来没被闸门验过**。

**怎么改**：`build.cmd` 增加 `verify-full`（build + vet + `go test ./...`，无 `-short`），
并在 release workflow 里改用它；同时记录本机耗时基线。

**验收**：`build.cmd verify-full` 能在可接受时间内跑完并全绿，耗时写进 `docs/集成报告.md`。

### P1 —— 结构收敛与安全（3–6 天）

#### P1-1 拆三个 god object（零 API 变更，风险最低）

| 文件 | 现状 | 建议切法（同包内拆文件，导出面不变） |
|---|---|---|
| `internal/engine/engine.go` | 1884 行 / 57 函数 | `events.go`（事件追加与 seq 推进）· `lifecycle.go`（submit/cancel/resume/finish）· `query.go`（status/events since） |
| `internal/worker/manager.go` | 1591 行 / 50 函数 | `manager.go`（worker 生命周期）· `pool.go`（池与并发）· `health.go`（健康与重启） |
| `internal/agent/loop.go` | 1413 行 / 40 函数 | `turn.go`（单轮装配：提示词/上下文）· `toolloop.go`（工具调用循环）· `finish.go`（usage 合并、回写、checkpoint） |

**验收**：`go build ./...` 与全部测试不变；每个新文件 < 600 行。

#### P1-2 死代码二选一（清单，全部经 grep 核实）

| 对象 | 现状（证据） | 建议 |
|---|---|---|
| `internal/storage/repository` 整包 | **零生产调用者**：`grep -rn "storage/repository"` 只命中注释与测试 | **接线或删**。其中 `ProviderRepo.ListEnabled`（`ORDER BY priority DESC, created_at ASC`）正是多 provider 候选池需要的东西 |
| `provider_requests` 资源类 | 只有声明与注释：`internal/types/t02_run.go:183`、`internal/scheduler/resource_pool.go:18`（注释）、`internal/tool/runtime.go:16/26`；**没有 acquire 点** | **接线**。后果是 LLM 调用没有独立并发硬上限，只靠"每 client 令牌桶 + 熔断 + 全局 32 run"间接约束 |
| `storage.Dispatcher`（outbox） | `internal/storage/outbox.go:260` 有构造器，**无生产调用者**（`engine.go:1097` 的 `Dispatcher` 是 scheduler 的字段，不是它） | 补生产启动点，或在文档里明确标为"预留" |
| `checkpoints` / `checkpoint_blobs` 两张表 | 只有 `internal/storage/repository/checkpoint.go` 在写（而该包无人调用）；生产快照实际写在 `kv` | 启用（把快照迁过去）或删表（新迁移） |
| `secrets.MigratePlaintext`、`provider.ResolveActiveProvider`、`CircuitBreaker.Reset/OnStateChange`、`RateLimiter.SetRate` | 均无生产调用者 | 删，或补注释说明用途与触发条件 |

**验收**：对每个符号 `grep` 一遍，除定义处外至少有一处生产调用点；否则删掉。

#### P1-3 IPC 加握手令牌（半天）

**问题**：进程间信任边界没有建模。`internal/ipc/protocol.go` 的帧头里没有凭据字段；
命名管道以 `lpSecurityAttributes=0` 创建（`internal/ipc/transport_windows.go`）；
TCP 绑回环。**同用户的任意进程**都能调 `system.secret.put` / `system.config.set` /
`engine.run.submit`（`internal/ipcapi/admin.go`）。

**影响（校准过的）**：**中等**。你没有提供读明文的接口（这点做对了），所以拿不到密钥；
但可以**覆盖**用户的密钥与配置、提交 run。

**怎么改**（两选一或都做）：
1. 引擎启动时生成 32 字节随机令牌，写到 `<BaseDir>/data/run/ipc-token`（0600），
   要求首帧携带；Supervisor 转发时透传。
2. 命名管道创建时传真实的 `SECURITY_ATTRIBUTES`（仅当前用户 SID 可访问）。

**兼容策略**：令牌文件不存在时按旧行为放行并打警告，两个版本后强制。

**验收**：一个不带令牌的第三方进程调用 `secret.put` 应被拒绝；前端与 CLI 都能正常带上。

#### P1-4 `internal/secrets` 跨平台化（顺带让 README 的声明成立）

**问题**：`internal/secrets/fallback.go` 无条件引用 `NewDPAPIBackend` / `CredentialBackend`
（Windows 专有且未加 build tag），加上 `internal/ipc/transport_unix.go` 的未用 import、
`internal/worker/procguard/guard.go` 的 `jobHandle`，导致 `GOOS=linux go build ./...` 直接失败，
而 README 写的是"Linux/macOS 后端可编译运行"。

**可参考的现成实现**：中转站网关为了在 Linux 上跑，已经做过同样的事——
`cmd/ximo-gateway/secrets_windows.go`（凭据管理器/DPAPI）+ `secrets_other.go`（0600 文件后端），
接口定义在 `secrets.go`。把同样的按平台拆分搬到 `internal/secrets` 即可。

**验收**：`GOOS=linux go build ./... && GOOS=darwin go build ./...` 通过，并在 CI 里开启 P0-1 的
linux/darwin 矩阵。

### P2 —— 正确性覆盖与工程卫生（1–2 天）

#### P2-1 真实上游 E2E（价值最高的"测试补强"）

**问题**：现有测试全部打替身。这次的**流式请求按 0 token 计费**就是"只测替身"的直接后果
——替身把 `usage` 放在 `finish_reason` 之前，而真实上游多数放在其后。

**怎么改**：加一个 `-tags e2e` 的用例，用环境变量提供真实 OpenAI 兼容 endpoint + key，
跑一次流式与一次非流式，断言 `usage` 非零且账目一致；CI 里作为可选 job（无密钥则 skip）。

**验收**：本地带密钥可跑通；不带密钥时明确 skip 而不是假装通过。

#### P2-2 帧协议加黄金字节用例

**问题**：29 字节定长帧在 Go（`internal/ipc/protocol.go`）与 TS（`frontend/src/shared/frame.ts`）
各有一份实现，靠人工保持字节对齐，没有共享用例。

**怎么改**：把一组十六进制样本放进共享文件（如 `docs/frame-golden-bytes.txt`），
两侧各写一个用例：解析样本 → 断言字段值；再由字段生成帧 → 断言字节串等于样本。

**验收**：任一侧改动字段偏移，另一侧立即红。

#### P2-3 checkpoint 的 kv 前缀扫描

**问题**：快照写进 `kv`（key 形如 `ckpt:<runID>:<seq 20 位补零>`），读取用
`key LIKE 'ckpt:<runID>:%'`。`kv.key` 是 BINARY 主键，前缀 LIKE 通常用不到索引
→ 快照多了会全表扫。审计表若照此放 `kv` 会同样退化。

**怎么改**：新增 `(prefix, updated_at)` 索引表，或把 runID 提成独立列改用等值查询。

#### P2-4 工程卫生

1. **7 个文件未 gofmt**（已核实）：
   `cmd/ximo-agent/integration_test.go`、`internal/ipc/client.go`、`internal/ipc/ipc_test.go`、
   `internal/observability/metrics.go`、`internal/observability/tracing.go`、
   `internal/supervisor/supervisor.go`、`internal/types/extras.go`。
   `gofmt -w` 一次即可，并纳入 P0-1 的 CI。
2. **注释与事实对齐**（已核实的不符）：
   - `internal/config/config.go` 与 `internal/bootstrap/secrets.go` 注释写 ref 形如
     `dpapi:deepseek`，实际是 `secretref:v1:<sha256 前 128bit hex>`；
   - 测试注释里出现的 `consumeTrailing` 函数在本仓**不存在**（真实实现叫 `drainTrailingUsage`）；
   - `docs/XIMO中转站-V1.md` 里若干行号引用已随版本漂移。
3. **发布卫生**：
   - tag 必须指向发布的那份代码（`v2.1.0` 的 tag 提交不在任何分支上，导致"最新代码"是哪份有歧义）；
   - 发布二进制的同时发布生成它的源码（当时 Go 引擎源码未公开）；
   - 安装包文件名跟版本走：`electron-builder` 读的是 `frontend/package.json` 的 `version`，
     发布流程里要同步（或显式传 `--config.extraMetadata.version`），否则会出现
     "v2.2.x 的 release 里挂着 `XimoAgent.Setup.2.1.0.exe`"。
4. **升级脚本**（注意：`release/` 目录只存在于旧分支，`v2` 分支没有它）：
   若恢复自动升级，健康探测不要指向 `127.0.0.1:28888/readiness`（全仓没有该 HTTP 服务端），
   改用 `ximo-agent --health`。`--migrate-only` 已在 `cmd/ximo-agent` 补上，那套脚本的契约现在成立。

## 六、落地顺序建议

1. **P0-1 + P0-2**（CI + 全量闸门）——先建机制，后面每一步都受它保护。
2. **P2-4.1**（`gofmt -w` 那 7 个文件）——让 CI 一开始就是绿的，避免"一上线就红"。
3. **P1-4**（`internal/secrets` 跨平台）——修完才能打开交叉编译矩阵。
4. **P1-2**（死代码二选一）——`provider_requests` 优先接线（它直接关系到稳定性）。
5. **P1-1**（拆 god object）——纯结构改动，测试全绿即可，风险最低但收益长期。
6. **P1-3**（IPC 令牌）、**P2-1**（真实上游 E2E）、**P2-2**（帧黄金字节）、**P2-3**（checkpoint 索引）。
7. **P2-4.2/3/4**（注释、发布卫生、升级脚本）。

## 七、复现方法

```bash
# 体量（排除后来新增的网关/账号/插件）
theirs() { find cmd/ximo-agent internal -name "$1" | grep -vE "internal/gateway|internal/quota|internal/account|cmd/ximo-gateway"; }
theirs '*.go' | grep -v _test | xargs cat | wc -l     # 引擎非测试行数
theirs '*_test.go'       | xargs cat | wc -l          # 引擎测试行数
theirs '*_test.go' | xargs grep -hoE '^func (Test|Fuzz)[A-Za-z0-9_]+' | wc -l

# 结构
grep -cE '^func ' internal/engine/engine.go internal/worker/manager.go internal/agent/loop.go
wc -l internal/engine/engine.go internal/worker/manager.go internal/agent/loop.go

# 死代码
grep -rn "storage/repository" --include='*.go' . | grep -v '^./internal/storage/repository/'
grep -rn "provider_requests" --include='*.go' internal
grep -rn "NewDispatcher" --include='*.go' internal cmd | grep -v _test

# 卫生
gofmt -l cmd internal tests

# 跨平台
GOOS=linux go build ./...
```
